## 2. 基準口徑修正：BENCH-v1 → BENCH-v2

### 2.1 兩個錯在哪

```python
# BENCH-v1（舊）：level(date) = mean(所有標的的 Close)，再除以第一天的 level
```

1. **不是報酬序列**。價格水位的平均不合成、不除權、不再平衡；高價股主導平均
   （每天前 5 大高價股佔平均價 12–17%）。拿它當「市場報酬」在數學上就不成立。
2. **母體被 `Close = 0` 汙染**。`daily_data2_full` 保留停牌／下市名稱的 0 收盤列：
   2026-08-01～11-30 期間有 **1,749 列、76 個交易日**（每天 4–32 列）。
   在等權日報酬鏈接裡，每一列 0 收盤都是 **−100% 的一天**，每天把等權平均拉低 1–3pp，
   56 天複利下把市場從 **−13.85% 壓成 −48.49%**。
3. **live 段基準重新歸一**：`live_bench_base = live_bench[0]['level']` → live 第一天
   基準恆為 0，把「市場當天跌多少」整個漏掉（live 超額 ≡ net）。

### 2.2 BENCH-v2 怎麼算

- 母體＝與選股**同一個** universe（`Close > 0`、4 位數台股代號）→ 基準與進場池同源。
- 每個交易日：所有「當日與前一日都有有效收盤」的標的之**日報酬等權平均**，逐日複利鏈接。
- 第一個 session 的 level = 1.0（帳戶在第一天的收盤進場，市場基準也從那天起算）。
- **算不出來就標 `null`**（level=None），絕不寫 0——寫 0 等於宣稱「市場今天沒動」。
- live 段**承接回溯段的 base**：live 的市場報酬 = level(live 末) ÷ level(live 前一交易日) − 1。

### 2.3 順手抓到的第二個 bug：滾動判定的窗口對齊

舊 `rolling()` 把「20 個交易日的淨報酬」去比「市場**自成立以來**的累計報酬」，
等於用 56 天的市場跌幅去卡 20 天的帳戶表現 → 判定線遠比 R9 寫的嚴格。
已改為**同一窗口兩邊都量**：帳戶 window 報酬 vs 市場 window 報酬，
並且**真的**把 R9 寫的「最大回撤 < 25%」納入（舊版根本沒檢查 MDD）。

### 2.5 又一個引擎 bug：規則只在「有發佈精選」的日子評估（2026-11-26）

`simulate()` 原本是這樣走迴圈的：

```python
for date in sessions:
    run = runs_by_date.get(date)
    if not run:
        continue          # ← 沒有發佈精選的日子，整個交易日被跳過
```

樣本裡 **70 個交易日中有 13 天沒有發佈精選**（2026-08-13～08-28、09-03，
因為當時市場螢幕還沒有每日跑）。在這 13 天裡引擎**什麼都沒做**：
停損不會觸發、持有天數不會累加、部位不重估、回撤曲線沒有那一點。
但在真實交易裡，帳戶是**每天**都要被檢查的（價格到了 −20% 就會停損，
不管今天有沒有發佈精選）。

**忠實度檢查**：在沒有缺口的 2026-09-04 之後（53 個交易日全部有發佈精選），
「舊引擎」與「每天評估」的引擎**逐筆交易完全相同、權益曲線完全相同**
→ 差異全部來自那 13 天，沒有別的原因。

| 項目 | 舊口徑（只在發佈日評估） | 新口徑（每個交易日評估） |
|---|---|---|
| 期間長度 | 57 個交易日 | **70 個交易日** |
| AIV1 淨報酬 | −22.21% | **−20.37%** |
| AIV1 超額（vs 市場 −17.76%） | −4.45pp | **−2.62pp** |
| AIV1 最大回撤 | −33.63% | **−33.89%** |
| AIV1 同期存款（1.7%／年） | +0.3820% | **+0.4694%** |
| AIV1 年化淨報酬 | −67.05% | **−55.96%** |
| H3 淨報酬 | +0.16% | **−2.16%**（正負號翻轉） |
| H3 超額 | +17.91pp | **+15.59pp** |
| H3 最大回撤 | −17.82% | −17.55% |
| live 第 1 天超額 | −1.43pp | −1.44pp |

**兩個重點**：
1. **MDD 幾乎不變**（−33.63% → −33.89%、−17.82% → −17.55%）→
   Walter 要選的「MDD 容忍」那一軸**是穩的**，不受這個 bug 影響。
   （因為那 13 天市場很溫和：gap 日的市場日報酬只有 −1.42% ～ +1.38%。）
2. **H3 的絕對報酬由正轉負**。之前說「H3 是唯一把絕對報酬翻正的變體」是錯的；
   正確的說法是「H3 在舊口徑下翻正，新口徑下沒有」。

**期間長度連帶修正**：存款基準與年化原本用「帳戶有決策的天數」（57），
但帳戶的錢在那 13 天仍然曝險在市場上 → 期間長度應該是 **70 個交易日**。
這個修正讓同期存款從 0.3820% 變成 0.4694%、年化從 −67.05% 變成 −55.96%。
（同樣的「期間長度」問題，在 2026-11-25 的第一次修正裡用的是 57，
所以那次只解掉了一半：年利率 vs 期間報酬解掉了，期間長度本身還差 13 天。）

**舊口徑的數字仍保留在頁面上並列顯示**（`metrics_published_days_only`），
但標為「已修正，僅供對照」，**不可再引用**。

## 6.5 H3′ 零股版：執行約束解除後的曝險配對超額

**「H3 與執行約束互斥」這條結論在零股下不成立。**

1. **n 太小**：H3 這個口徑只有 26 筆買進、**21 筆已平倉**；
   **前 3 筆貢獻 159% 的實現損益**（−42,386 → +242,380 之間的跳躍全靠三筆）。

**誠實結論**：H3 在「零股＋次日開盤」這一格是唯一同時贏過市場、贏過存款、

## 9. 六句誠實結論（2026-11-26 更新）

1. **AIV1 在所有執行設定下都是負的**：32 個組合（零股／整股 × 兩種成交模型 × N=6/8/10/12）
   沒有一格是正的，最好的一格是「整股＋NEXT-OPEN＋N=10」的 −8.65%（曝險 49.7%，

2. **H3 在「零股＋次日開盤＋N=6」這一格是唯一贏過市場又贏過存款的組合**
   （淨 +6.63%、曝險配對 +16.61pp、MDD −16.46%），**但它的可信度不足以稱為 edge**：
   21 筆已平倉、前 3 筆貢獻 159% 損益、換成 FILL-CLOSE 淨報酬就變成 −3.51%、
   而且是 14 個變體裡 in-sample 挑出來的最大值。它現在的定位是**影子帳**。
3. **樣本只有 70 個交易日、兩個 regime**：等權市場 2026-08 +0.61%、09 +2.14%、
   10 −4.24%、11 −12.46%；樣本內沒有真正的牛段可供驗證規則在多頭 regime 的表現。
4. **低曝險規則在空頭母體裡的正報酬不能當成選股 edge**：
   曝險配對對照組是唯一的判準（隨機選檔 20 seeds 的中位是 −9.79pp）。
5. **本輪所有設定（規則、成交模型、部位數、停損）都是在同一段資料上挑的，屬 in-sample**；
   live 段（自 2026-11-25）是目前唯一的前瞻母體，且只跑了 1 天。
6. **兩次口徑修正的影響方向相反，必須一起看**：
   基準修正（BENCH-v2）讓超額從 +8.86pp 變成 −4.45pp（變難看）；
