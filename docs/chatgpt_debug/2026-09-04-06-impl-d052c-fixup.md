## Issues caught

### I1. Remote main was 3 commits behind local
- **Found by**: ChatGPT review (visible UI)
- **Cause**: After the first push at 7b326bc, I did 3 more commits (9f35b42, b199c03, 0f1dc73) but never pushed them. I incorrectly reported "6 commits 已 push" — that was wrong.
- **Fix**: `git push origin main` → `7b326bc..0f1dc73 main -> main` ✅
- **Lesson**: Always run `git status -sb` or `git rev-list --count origin/main..HEAD` to verify push state, not just trust my own log.

### I2. Filter order: row-level type filter missing
- **Found by**: ChatGPT review (visible UI)
- **Issue**: The script grouped rows by ticker AFTER date filter, then checked `if not (types & {"twse", "tpex"})` at the per-ticker level. A ticker with mixed `emerging` + `twse` rows on current_date would pass the per-ticker check but include emerging rows in the group.
- **Fix**: Added row-level `type IN ('twse', 'tpex')` filter BEFORE per-ticker grouping. Drops 363 emerging rows on current_date 2026-09-04.
- **Verified**: Re-ran with same 12 allowlist → same 7 promote / 5 quarantine split. Log now shows `dropped 363 rows with type not in (twse, tpex)`.

### I3. TLS verification disabled
- **Found by**: ChatGPT review (visible UI)
- **Issue**: `ssl.create_default_context()` then `ctx.check_hostname = False; ctx.verify_mode = ssl.CERT_NONE` — disables all cert validation.
- **Root cause**: Windows + Python 3.14 + OpenSSL has issues with FinMind cert chain (`Missing Subject Key Identifier`). I worked around it by disabling verification rather than fixing the cert bundle.
- **Fix**: Use `certifi` CA bundle (`certifi.where()`) which has the full Mozilla CA store including the chain FinMind needs. If `certifi` is not installed, fall back to system trust store. **NEVER disable verification.**
- **Verified**: `import certifi; certifi.__version__ == '2026.05.20'` is present on this system. Script now uses it.

## Bonus fix: idempotency for recurring run (D052d)

### I4. No skip-if-already-resolved check
- **Issue**: Re-running the script for the 12 allowlist would re-INSERT the 7 to industry_type (no-op via ON DUPLICATE KEY UPDATE) but re-INSERT the 5 to metadata_quarantine, accumulating duplicate rows. After 2 runs, quarantine was 10.
- **Fix**: Pre-load `industry_type.ticker` and `metadata_quarantine.ticker WHERE resolved_at IS NULL`. Skip allowlist tickers that are already in either set. Print explicit "skipping N already-resolved tickers" message.
- **Verified**: Re-run with same 12 → "skipping 12 already-resolved tickers" → "nothing to do".
- **Cleanup**: Deleted 5 duplicate quarantine rows from the pre-fix re-run. Back to clean state: 5 open quarantine.
