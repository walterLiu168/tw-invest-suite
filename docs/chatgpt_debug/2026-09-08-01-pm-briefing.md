### 9.3 建議目標架構

```
Task Scheduler
      │
      ▼
Daily Orchestrator ─── run_id / data_date / commit SHA
      │
      ├── Data gates：OHLCV、法人、融資券、metadata
      ├── Compute：screen transaction（24 picks）
      ├── Render：MD / HTML / prompt / watchlist
      ├── Verify：日期、數量、NULL、hash
      └── Publish：GitHub Pages → Tunnel secondary
                         │
                         ▼
                Postflight + Alert
```

排程時間可以保留，但依賴關係必須以 data_date 與 marker 判斷，不能只假設「前一個 cron 應該已跑完」。

### 9.4 單一程式來源決策

建議採：
- **Git repo**：唯一 source of truth
- **Versioned runtime release**：唯一 production 執行位置
- **Atomic deploy script**：唯一同步方式

每次部署將指定 commit 複製到例如 `runtime/releases/<sha>/`，通過 compile 與 unit tests 後原子切換 `runtime/current/`。Task Scheduler 全部只呼叫 `runtime/current/`；禁止部分 cron 直接跑 git repo、部分跑 `.claude\skills` 鏡像，也禁止手動修改 runtime 檔案。

### 9.5 資料主權

| 資料 | Canonical | 其他用途 |
|---|---|---|
| OHLCV | `daily_data2_full` | 其他價格表只能 derived / legacy |
| 公司名稱與產業 | `industry_type`（短期維持） | FinMind staging / quarantine 負責候選與稽核 |
| 每日選股 | `market_screen_runs` + `market_screen_picks` | HTML 不得成為狀態來源 |
| 發布狀態 | 新增 publish manifest / run ledger | Scheduler result 及 log 僅為輔助證據 |
| 4 張 legacy tables | derived | 必須記錄 source date 及 sync run |

**暫時不建議把 `stock_info` 升為 canonical**。先完成欄位責任與同步契約；若需要 ListedDate，可建立統一的 `security_master` 設計提案後再遷移，不應在目前穩定化階段直接換主表。
