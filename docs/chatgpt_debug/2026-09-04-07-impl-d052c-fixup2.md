## Issues caught and fixed

### I5. `--all` flag still present though not approved
- **Found by**: ChatGPT review
- **Issue**: `metadata_backfill.py --all` would process all twse/tpex 普通股. Per D052c review, full-universe is not approved (name filter is insufficient for safety).
- **Fix**: Removed `--all` arg entirely. Script now requires `--batch=...`. Hard fail otherwise.

### I6. Dead per-ticker type check (redundant with row-level filter)
- **Found by**: ChatGPT review
- **Issue**: `if not (types & {"twse", "tpex"})` per-ticker check is dead code — row-level filter already dropped non-(twse/tpex) rows before grouping.
- **Fix**: Removed the dead check. Code path is cleaner.

### I7. Allowlist missing tickers only WARN, not quarantine
- **Found by**: ChatGPT review
- **Issue**: Tickers in allowlist but absent from FinMind on current_date only got a `WARN:` line. Per Q3 strict rule, missing tickers must be quarantined (not silently dropped).
- **Fix**: Compute `absent = allowlist - found` BEFORE per-ticker loop. Absent tickers get a quarantine row with reason `"allowlist ticker absent from FinMind on current_date (YYYY-MM-DD)"`.
- **Verified**: `--batch=9999,3485` → 9999 → QUARANTINE (absent), 3485 → skipped (promoted).

### I8. Quarantine re-inserts on every run (no event fingerprint)
- **Found by**: ChatGPT review
- **Issue**: First re-run after D052c inserted 5 duplicate quarantine rows. Even with my prior "already-resolved skip", a recurring run with the same FinMind state would re-insert.
- **Fix**: Per-event fingerprint `(ticker, source_date, reason)`. Pre-flight loads open fingerprints. Insert step skips if fingerprint already open.
- **Critical detail**: MySQL returns `source_date` as `datetime.date` object, but new code uses ISO string. Both must be normalized to ISO string for comparison. **First fix attempt was buggy** — dedup didn't work because of type mismatch. Re-ran and confirmed 5 skipped as duplicate fingerprint.

### I9. Staging accumulates duplicates (no UNIQUE constraint)
- **Found by**: ChatGPT review (implicit — same family as I8)
- **Issue**: `metadata_staging` had no UNIQUE index, so every run would re-insert the same (run_id, ticker, source_date, industry_category, type, stock_name) tuples.
- **Fix**: 
  1. Added UNIQUE index on `metadata_staging (run_id, ticker, source_date, industry_category, type, stock_name)`
  2. Changed `INSERT INTO` to `INSERT IGNORE INTO` in `insert_staging()`
  3. `cur.rowcount` reports actual inserts (after dedup)
- **Verified**: Re-run with same 12 → "inserted 13 rows" but staging table count stayed at 92 (all duplicates skipped).
