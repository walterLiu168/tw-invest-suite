## 1. metadata marker BOM interoperability

### 1.1 問題

現存 marker `metadata_target_2026-09-04_OK.marker` 是 Windows PowerShell 5.1
的 `Set-Content -Encoding UTF8` 寫入的，**開頭有 EF BB BF BOM**。D052h-fixup3
的 `has_metadata_marker` 用 `encoding="utf-8"` 讀，第一個 key 變成
`\ufefftarget_date`，`info.get("target_date")` 回 None，函式 return False。

### 1.2 修法

#### 1.2.1 producer：`scripts/metadata_backfill_daily.ps1`

把 `Set-Content -Encoding UTF8` 換成 `[System.IO.File]::WriteAllText` + `UTF8Encoding($False)`：

```powershell
$Utf8NoBom = New-Object System.Text.UTF8Encoding($False)
[System.IO.File]::WriteAllText($TempMarker, $MarkerContent, $Utf8NoBom)
```

`Set-Content -Encoding UTF8` 在 Windows PowerShell 5.1 永遠寫 BOM，
`utf8NoBOM` 是 PowerShell 7+ 才有的 encoding literal，5.1 必須用 .NET API。
`Move-Item` atomic rename 邏輯保留。

#### 1.2.2 consumer：`scripts/market_screen_runner.py:124`

`has_metadata_marker` 讀 marker 從 `encoding="utf-8"` 改為 `encoding="utf-8-sig"`：

```python
content = marker.read_text(encoding="utf-8-sig", errors="ignore")
```

`utf-8-sig` 在讀取時會自動剝掉 leading BOM，沒 BOM 的也照常處理。
向後相容舊 BOM marker，向前相容新 BOM-less marker。

### 1.3 驗收

```

=> True  ✓
```
