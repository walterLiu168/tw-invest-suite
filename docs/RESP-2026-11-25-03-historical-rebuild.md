# 歷史重建：2020–2026 市場螢幕精選訊號（Phase 1）

> 對應 `docs/RESP-2026-11-25-02-ai-ledger-survival-sweep.md` 的下一段工作。
> 授權依據：**Walter 2026-11-25**（「全面授權」＝重建全部歷史 ＋ 重建 ML 權重 ＋ 解除 9/30 handover 邊界）。
> 本文件記錄的是**重建的可行性與驗收閘門狀態**，不是重建完成報告。

---

## 0. 一句話

重建**可行且已被證明忠實**（G1：2026-11-24 重建出 24/24，逐欄一致），
但**單日 156 秒** → 2020–2026 約 1,660 個交易日需要約 **72 小時**單行程；
而且輸入資料有硬缺口（籌碼表只回溯到 2024-01-02、特徵表有空洞），
所以「能重建的日期範圍」需要先被界定清楚。

## 1. 為什麼不用 `scripts/market_screen_runner.py`

| 限制 | 位置 | 為什麼不行 |
|---|---|---|
| `--data-date` 必須等於最新資料日 | `market_screen_runner.py:519-525` | 直接擋掉歷史日期 |
| `persist_atomic()` 會把**更早**的 active picks 全部 CLOSE | `market_screen_runner.py:313-320` | 回填一個歷史日就會把今天那 24 檔關掉 → **G4 違規** |
| 需要 `metadata-backfill` 成功 marker | `market_screen_runner.py:553-556` | 歷史日期沒有 marker |
| 產物（MD／HTML／deep-dive）寫到共用的 REPORT_DIR | `generate_artifacts()` | 歷史批次會覆蓋今天的產物 |

→ 改寫成**離線重建**：呼叫同一支 `market_screen.screen_market()`，
把結果寫到 `scripts/_debug/_history_picks/<date>.json`（gitignored）。
**完全不碰 `market_screen_runs` / `market_screen_picks`** → G4 天然滿足。

## 2. 怎麼保證沒有前視

| 資料來源 | 原始行為 | 重建時怎麼鎖到當日 |
|---|---|---|
| `db.market_snapshot()` | 用 `latest_date('daily_data2_full')` | 把 `db_client.latest_date` 換成目標日 → 讀到當日快照 |
| `db.ticker_history()`（zen 分析用） | cutoff = `as_of or query_date()` | `db_client.report_date(d)` context 綁定 → cutoff = 目標日（**含當日收盤**，與 live 執行時一致） |
| `db.long_term_returns_batch()` | 吃 `target_date` | 目標日 |
| `db.news_for_tickers()` | 吃 `target_date` | 目標日 |
| `db.all_latest_chipscore()` / `all_latest_features()` | 吃 `target_date` | 目標日 |
| `db.all_industries()` / `all_shares_outstanding()` | 現況 | **殘留前視**：產業分類與股本用的是「現在」的對照。影響小（只影響分類欄位與市值），但要寫在揭露裡 |

## 4. G1 的已知失敗模式（很重要）

`enforce_features=True`（live 排程用的路徑）會呼叫
`db.assert_feature_freshness(target_date, tickers, min_coverage=0.95)`，
而 `stock_features` 在 2026-08-12～08-19 期間**整段是空的**（0 列）→ 直接 raise：

```
stock_features freshness gate failed: date=missing expected=2026-08-12 rows=0/1943 coverage=0.0% required=95.0%
```

這代表：

1. **DB 裡那些日期的精選，本來就是在「特徵表沒有該日資料」的狀態下產生的**。
2. 重建要能重現它，就必須用 `--no-features`（不做特徵鮮度斷言），
   否則會在 2026-08 那一段全部失敗。
3. 更早的日期（例如 2024 以前）特徵表同樣稀疏 → 那些日期的重建是
   **「另一個輸入組合下的螢幕」**，不是「當時真正跑過的螢幕」。
   → 重建結果必須標註每個日期的輸入完整度，不能混為一談。

## 5. G3 存續偏誤（母體變化）

| 年 | 當年有交易的標的數 | 交易日 |
|---|---|---|
| 2020 | 1,862 | 245 |
| 2021 | 1,892 | 244 |
| 2022 | 1,926 | 246 |
| 2023 | 1,957 | 239 |
| 2024 | 2,008 | 242 |
| 2025 | 2,019 | 243 |
| 2026（至 11-25） | 2,063 | 209 |

母體 7 年成長 10.8%（1,862→2,063），每年 +1.5–2%。
**已知限制**：`daily_data2_full` 只含**現存**標的 → 已下市的股票不在任何一年的母體裡，
這是存續偏誤，**不可用未來的存續名單修補（那就是前視）**。
偏誤的量級無法從 DB 內部量化（缺的是「當年存在、現在已死」的名單），
只能揭露。實務影響：回測會系統性高估「買得掉」的假設。

## 6. G5 成本實測

| 項目 | 數值 |
|---|---|
| 單日重建耗時（2026-11-24，含 import 暖機） | **155.9 秒** |
| 全期交易日數（2020-01-02～2026-08-11） | 約 1,620 |
| 單行程全期估計 | **約 70 小時** |
| 4 行程平行估計 | 約 18 小時 |
| 目前可用的日期 | `daily_data2_full` 有 Close>0 且 4 位數代號的交易日 |

**建議批次切法**：依月份切 shard，每個 shard 一個行程，輸出到
`scripts/_debug/_history_picks/<date>.json`（已存在就跳過 → 可中斷續跑）。
跑完再做 G2 的截斷對照，最後才把長樣本拿去掃規則。

## 7. 輸入資料的涵蓋與硬限制

| 表 | 最早 | 最晚 | 對重建的影響 |
|---|---|---|---|
| `daily_data2_full` | 2020-01-02 | 2026-11-25 | 價格／技術面／籌碼欄位的主來源 ✔ |
| `stock_features` | 2001-06-01 | 2026-11-25 | **有空洞**（2026-08-12 整段 0 列、2026-06-01 也是 0 列）→ 特徵新鮮度閘門會擋 |
| `chipscore_daily` | **2024-01-02** | 2026-11-25 | 籌碼分數只回溯到 2024 → **2024 年以前的重建是「無籌碼」的螢幕**，排序會不同 |
| `finmind_taiwan_margin_maintenance` | **2026-08-07** | 2026-11-25 | 130% 硬規則的歷史只有 3 個月 → 危險頁的回溯窗**無法往前推** |
| `market_screen_runs` | 2026-08-12 | 2026-11-25 | 現有精選只有 57 輪 |
| `model_predictions_daily` | **2026-06-15** | 2026-11-25 | 現行 ML 只涵蓋 51 天 → 只够用在 56 日窗，**不能用在長樣本** |
| `xg_predictions_daily` | 2014-10-14 | **2025-08-29** | 舊 XGB 涵蓋 2,657 天、860,212 列 → 可用在歷史段，但**在 live 窗之前就斷了** |

→ **ML 因子有兩段互不重疊的覆蓋**（2026-06-15 起 / 2014–2025-08-29），
任何「含 ML 因子」的規則都必須分段報，**不能與不含 ML 的長樣本放在同一張表比較**。

## 8. regime 地圖（等權日報酬鏈接，2020-01-02～2026-11-25）

| 年 | 交易日 | 報酬 | 日均 |
|---|---|---|---|
| 2020 | 244 | **+21.94%** | +0.0887% |
| 2021 | 244 | **+33.70%** | +0.1259% |
| 2022 | 246 | −3.04% | −0.0060% |
| 2023 | 239 | **+26.96%** | +0.1016% |
| 2024 | 242 | +11.24% | +0.0482% |
| 2025 | 243 | +0.96% | +0.0121% |
| 2026（至 11-25） | 209 | −7.58% | −0.0259% |

**這是本次重建的真正價值**：現有 57 天的樣本只有一個空頭 regime，
但 2020／2021／2023 是明顯的牛段。
「H3（均值回歸、e240>0 且 e60<0）」在牛段會是什麼表現，
**只能在多 regime 母體上回答**——這是 Phase 1 存在的理由。

樣本期分月（等權日報酬）：

| 月 | 報酬 | 日均 |
|---|---|---|
| 2026-08 | +0.61% | +0.0543% |
| 2026-09 | +2.14% | +0.1098% |
| 2026-10 | −4.24% | −0.2351% |
| 2026-11 | −12.46% | −0.9503% |

→ 樣本**不是**單一空頭 regime：前兩個月是上漲的，後兩個月是加速下跌。
（此前「每月都跌」的說法已被這組數字推翻。）

## 9. 下一步

1. 擴大 G1 到 10–20 個日期（含 2024-01 以前，確認「無籌碼」年代的重建品質）。
2. G2 截斷對照：對 3 個日期，把資料截斷到當日重跑，輸出須與全量跑一致。
3. 依月份切 shard 的平行批次重建（4 行程，約 18 小時），背景跑、不佔前景。
4. 重建完成後，把第 2 節的規則族（baseline／H0 排序／H2 方向／H3 及雙腿消融／kill switch）
   在**多 regime 母體**上重跑 → 這才是定案的依據。
5. AIV2 的程式實作（kill switch、整股執行層、影子帳）等 Walter 決定後再做；
   live 段維持 AIV1 不動。
